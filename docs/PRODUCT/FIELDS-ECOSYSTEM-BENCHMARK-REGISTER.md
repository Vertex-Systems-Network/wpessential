# Fields Ecosystem Benchmark Register

Snapshot: 2026-08-31

Status: active discovery register for Surface 3 (`fields`). This register is evidence for the Master Options & Possibilities Bank; it is not a claim that every listed competitor capability will ship unchanged.

## Research rule

WPEssential normalizes capabilities, not vendor implementations. GPL/public source may be inspected for behavior and option semantics. Proprietary or nulled code is never copied. Raw executable PHP/JS/eval-style configuration is not adopted; the Bank records a typed/provider-based or sandboxed alternative where the capability is useful.

WordPress.org plugin pages are treated as the canonical directory evidence and also expose the official plugin SVN/development history. GitHub/GitLab repositories are used as source-level evidence where an authentic project or maintained mirror can be established. Anonymous mirrors, nulled premium copies, and unverifiable archives are discovery hints only and cannot establish an implementation contract.

## GitLab and other Git remotes

Public GitLab search was used to identify ACF/extended-field mirrors and field framework experiments. Because many results are mirrors or redistributed premium packages, GitLab evidence is accepted only when provenance can be established. Unverified mirrors do not justify copying code or marking an option as reviewed.

The same rule applies to any Git hosting service: capability discovery is broad; implementation provenance must be trustworthy.

## Newly normalized market gaps in this wave

This sweep added canonical support for specialized inputs such as phone, currency, code editor, Markdown, visual/radio image, calculation, unit/angle/alignment controls, combobox/token/static-content patterns; field/group role and capability policy; unique-value constraints; character/word counters; per-location overrides; JSON/PHP/YAML schema sync; live code/schema export; block bindings and block-local editing; structured REST schema generation; relationship inline create/edit/list UX; glossary/query choice sources; global/template/page value hierarchy; and a broad migration-adapter matrix.

## WPEssential exceed direction

WPEssential should exceed the ecosystem through safer and more inspectable customization rather than raw callback freedom. Current exceed candidates include schema versions and aliases, drift/conflict detection, access/location/conditional simulators, raw-to-stored value previews, safe formula ASTs, provider SDK and extension sandboxing, per-field cache/index/governance policies, migration dual-read/dual-write with validated cutover and rollback snapshots, generated contract tests/fixtures, block-binding policies and accessibility diagnostics.
