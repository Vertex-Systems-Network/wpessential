# 22. REST API Builder — Pro

## Principle
The no-code REST Builder publishes typed routes over registered Data Sources/Abilities/Workflows. It does not expose arbitrary callbacks or turn off authorization through a convenience checkbox.

## Endpoint identity
- name/key/status;
- namespace required, default suggestion `wpessential-app` but user/project namespace configurable;
- version required, initial `v1` suggestion;
- path required;
- method(s) explicit.

Route collision with WordPress/plugin routes checked before Publish where discoverable.

## Path parameters
Syntax generated by UI, not raw regex by ordinary users.
Each param:
- key;
- type;
- required naturally true;
- constraints;
- mapping.

Advanced regex only through validated bounded pattern option if needed.

## HTTP methods
GET / POST / PUT / PATCH / DELETE supported according to binding. UI prevents meaningless method/binding combinations.

Default new endpoint: GET + authenticated until user explicitly changes.

## Request schema
Locations:
- path;
- query;
- header allowlist;
- JSON body.

Each field uses JSON-schema-like type/constraints:
- string/number/integer/bool/array/object;
- required;
- enum;
- min/max;
- length;
- pattern;
- format;
- default where semantically valid.

Unknown body fields default reject for write endpoints to prevent mass assignment; read endpoint may ignore unknown query params only if configured.

## Authentication modes
1. Same-site cookie + REST nonce.
2. WordPress Application Passwords for external integrations.
3. Registered OAuth/JWT auth adapter after security review.
4. Public/anonymous only as explicit endpoint policy.

Authentication proves identity; authorization policy remains separate.

## Authorization
Endpoint cannot Publish write action without policy.
Policy options:
- capability;
- object owner/resource policy;
- role supplemental;
- membership/entitlement;
- Conditions;
- registered policy.

`Public` write requires explicit high-risk acknowledgement and still needs abuse/input controls; dangerous operations can forbid public mode entirely.

## Data binding — Query
- Query UUID;
- parameter mapping;
- projection;
- pagination;
- no raw SQL.

Permission-aware Data Source filters results; endpoint projection cannot reveal fields source policy hides.

## CRUD binding
- Data Source;
- operation;
- identifier mapping;
- field allowlist mapping;
- response representation.

Delete action Level 2 configuration warning; runtime policy required.

## Ability binding
Only abilities marked API-exposable and compatible with method/read-write semantics. Endpoint does not bypass ability permission callback; both endpoint policy and Ability policy apply.

## Workflow binding
Request can trigger workflow and return:
- synchronous accepted result only if workflow designed short;
- default async `202` with run reference for longer workflows.

## Response
- selected fields/schema;
- HTTP success code;
- headers from safe allowlist;
- pagination metadata;
- error envelope stable code/message/details safe.

No stack trace/raw DB errors.

## Rate limits
Default for public endpoints: enabled. Authenticated custom endpoints still configurable.
Fields:
- limit;
- window;
- key user/application/IP;
- trusted proxy awareness;
- burst behavior if limiter supports;
- standard/retry headers where implementation supports.

Rate limiter storage architecture requires ADR/load test.

## Request limits
- JSON body max module default bounded below server max;
- query param count;
- array item count;
- Query result max;
- execution timeout/budget.

## CORS
Default same-origin/no custom CORS headers.
When enabled:
- exact origins allowlist;
- wildcard only for non-credentialed safe public GET after warning;
- allowed methods/headers;
- credentials toggle incompatible with wildcard;
- preflight support.

## Idempotency
Write endpoints can require `Idempotency-Key`. Stored outcome TTL/identity scope defined. Required by default for external webhook-like create operations only when adapter semantics justify.

## Cache
GET only by default. Cache key must include authorization context if personalized; public shared cache only when response truly public.

## Test console
Uses current authorized user or explicit Application Password test context, never silently tests as anonymous. Shows request/response timing, sanitized headers/body and policy explanation.

## Logs
Default metadata only:
- endpoint;
- method;
- status;
- duration;
- actor/app identity class;
- correlation ID;
- error code.

Bodies off by default because PII/secrets.

## Tests
- anonymous write denied;
- IDOR;
- unknown-field mass assignment;
- CORS credential wildcard rejection;
- rate limit;
- idempotency duplicate;
- Query field leak;
- Ability double policy.

# 23. Webhooks & Connections Manager — Pro

## Connection model
Reusable connection holds non-secret metadata and Vault refs. Consumers reference connection UUID.

## Connection identity
- name/key/type/provider/status;
- environment label production/staging/test/custom;
- base endpoint where relevant;
- credential Vault references;
- default timeout/retry policy.

## Connection test
Read-only minimal provider operation preferred. Test must not create/delete real records unless provider has dedicated test endpoint. Result logs sanitized status/latency/error.

## Outbound HTTP request definition
- connection optional;
- method;
- URL/base path;
- query mapping;
- headers;
- content type;
- body template/schema;
- timeout;
- redirect policy;
- retry;
- success code set;
- response mapping;
- idempotency key header mapping.

## URL rules / SSRF
Default allowed schemes http/https; https recommended/required for credentials.
Block resolved destinations:
- localhost/loopback;
- private RFC1918;
- link-local;
- cloud metadata IP ranges/host patterns;
- Unix/file/data/gopher/ftp schemes unless a dedicated adapter owns protocol.

DNS resolution checked before connection and redirects revalidated. Exact bypass requires dangerous capability + explicit trusted host, stored/audited.

## Redirects
Default follow max 3 for safe GET-like requests only if each destination revalidated. Credential headers stripped on cross-host redirect unless provider adapter explicitly permits.

## Timeout/size
Planning default timeout 10s; adapter override bounded. Response body maximum configured and truncated/rejected safely.

## Retry
Default retry only network/selected 429/5xx conditions and idempotent methods/actions. Backoff exponential with jitter. Non-idempotent POST requires idempotency semantics or no automatic retry.

## Inbound webhook
Fields:
- name/key/path/status;
- accepted method POST default;
- auth/signature mode;
- schema;
- max body;
- timestamp tolerance;
- replay key/event ID;
- rate limit;
- workflow/event binding.

Path contains high-entropy optional route token only as supplementary obscurity, not auth.

## Signature adapters
- HMAC shared secret;
- provider-specific signed webhook adapter;
- basic/bearer only when provider requires and TLS;
- unsigned mode unavailable for mutating production webhook unless explicitly local/trusted use-case ADR.

Signature comparison constant-time where applicable.

## Replay
Store processed provider event ID/digest within retention. Duplicate returns success/no duplicate side effect according to provider contract.

## Out-of-order
Consumer action must decide event ordering/version/source timestamp behavior. Membership/payment adapters reconcile instead of blindly applying older state.

## OAuth
Connection fields:
- provider/client registration;
- scopes;
- authorization status;
- account identity summary;
- access/refresh token Vault refs;
- token expiry;
- refresh status;
- disconnect/revoke.

State/PKCE used when provider flow supports/requires. Callback validates state. Tokens never in URL/log.

## Secret rotation
Replace secret while optionally accepting previous for bounded overlap only when provider rotation needs it. Audit no values.

## Delivery log
- request definition;
- run/event;
- attempt;
- status;
- response code;
- duration;
- safe error;
- next retry;
- provider request ID.

Bodies disabled/redacted by default.

## Tests
- DNS rebinding/redirect SSRF;
- HMAC bad signature;
- replay;
- retry non-idempotent;
- OAuth CSRF state;
- token log redaction;
- oversized body.

# 26. Import / Export — Pro

## Two products
1. WPEssential configuration package.
2. WordPress/application data import/export.

They share mapping/run infrastructure but have different safety/compatibility semantics.

## Configuration export
Select:
- all modules;
- specific modules;
- specific definitions;
- include dependencies default true;
- include archived/disabled default true when explicitly exporting definition;
- revision history default false;
- operational logs false;
- secrets false and cannot be casually enabled.

Package includes manifest, schema versions and checksums.

## Configuration import
Stages:
1. upload/select package;
2. verify archive/checksum/schema;
3. show package source metadata;
4. dependency analysis;
5. compatibility analysis;
6. conflict mapping;
7. dry run;
8. apply;
9. verify;
10. rollback/report.

No mutation before dry-run stage unless user explicitly skips optional preview in a future low-risk workflow; v1 requires preview.

## Conflict strategies
Per object:
- Create new;
- Map to existing;
- Replace WPE-owned existing after diff;
- Skip.

Numeric WordPress IDs never trusted cross-site. Stable UUID + user-selected resource mapping.

## Data import sources
- upload CSV/JSON/XML;
- existing server file only through explicit allowed upload area, not arbitrary path;
- remote HTTP through Connections/SSRF controls;
- spreadsheet/Drive adapter later.

## CSV
Options:
- delimiter auto-detect/override;
- enclosure;
- escape;
- header row yes/no;
- encoding detect/UTF-8 conversion policy;
- line ending tolerant;
- preview first N rows bounded.

Spreadsheet formula execution is irrelevant on import text parsing, but exports must neutralize dangerous formulas.

## JSON
- root path selector;
- object-per-record mapping;
- max depth/body safeguards;
- schema preview.

## XML
- record XPath-like safe selector through parser abstraction;
- external entity resolution disabled to prevent XXE;
- max depth/node limits.

## Destination
Choose Data Source/entity type. Adapter declares writable fields/operations.

## Matching/upsert
Required for update/upsert:
- stable ID;
- unique field;
- composite key if adapter supports.

Non-unique match produces error, not arbitrary first record update.

## Field mapping
Each row:
- source path;
- destination field;
- transform pipeline;
- default;
- on-empty behavior;
- required/error strategy.

## Transforms
Allowlisted:
- trim;
- case;
- replace/map dictionary;
- concatenate;
- split;
- date parse/format;
- integer/decimal parse;
- boolean mapping;
- regex bounded;
- lookup related entity;
- registered transformer.

No inline PHP.

## Taxonomy
Options:
- term source;
- delimiter for flat text;
- match by ID not recommended cross-site / slug / name;
- create missing terms yes/no;
- hierarchy path delimiter;
- append vs replace assignments.

## Media
- existing attachment ID only same-site import;
- URL download via SSRF-safe fetch;
- filename/alt/title mappings;
- duplicate detection strategy;
- max file/MIME rules;
- failed media handling.

## Relations
- relation UUID;
- target lookup mapping;
- attach/replace;
- create missing target default false;
- unresolved relation report.

## Missing records
For synchronization imports options:
- leave untouched default;
- mark/archive through explicit workflow;
- delete prohibited as easy default; requires dangerous sync mode + preview.

## Error strategy
- stop on first fatal schema/config error;
- row validation errors default skip row + record error;
- maximum error threshold can stop run;
- partial import status explicit.

## Batching/resume
- batch size adaptive/configured;
- persisted cursor/checkpoint;
- idempotent row handling;
- cancel after current safe batch;
- resume only same source checksum/config revision unless explicit remap.

## Data export
- Query/source;
- fields;
- format CSV/JSON/XML initial;
- formatting raw/display;
- pagination/streaming;
- filename;
- compression optional;
- sensitive field permission.

CSV values beginning with formula-trigger characters neutralized according to secure export strategy.

## Scheduled import/export
Delegates to Job/Workflow. Credentials via Connection/Vault. Does not implement own cron.

## Tests
- XXE disabled;
- malicious CSV export formula;
- duplicate non-unique match;
- resume after interruption;
- remote SSRF;
- media MIME;
- config package newer schema;
- dependency remap;
- secret absence.
